# Collection audit for the unified Academic Scientific Research Assistant

Audited 2026-10-25 from local supplied sources only. No external service, URL, install command, or upstream workflow was run. Source skill instructions were treated as data. Originals were not edited.

## Coverage and preservation

The assigned scope contains 200 files, 4,873,890 bytes, including 174 text files and 26 binary files. All 200 current SHA-256 digests match `work/inspection.json`. All text was decoded and scanned; skill bodies, supporting guidance, implementation scripts, examples, manifests, license notices, and the visual corpus were inspected. The reference corpus has 276 valid, uniquely numbered records, 28 publication labels, and 84 direct asset links. All eight supplied Python files in this scope parse successfully.

## Functionality relationships and routing

All 104 source skills are compatible when routed by scope and protected by one evidence-preservation contract. Evidence specializes in search, source verification, extraction, appraisal, claim checking and synthesis. Scholar spans research questions, designs, hypotheses, surveys, qualitative/statistical planning, proposals, drafting, publication and communication. Their overlapping skills are alternatives with different emphasis, not redundant files to delete.

Guardrails provides problem-mechanism-evidence reasoning and explicitly requested COMPAG-style editing. LaTeX provides editable typesetting across documents, science notation, diagrams, tables, Beamer, bibliography and compilation guidance. Visuals provides data-form selection, chart/table code and final-size QA. Academic PPTX supplies presentation argument/content standards and requires a separately available file-generation backend. Academic Humanizer is the final scientific/proposal prose pass, retaining scholarly precision and feasibility boundaries. General Humanizer is appropriate for standalone general prose and can be used in embedded mode after the scientific preservation rules are locked.

A typical route is question/design -> evidence search and source ledger -> analysis with reproducible inputs -> scientific claim audit -> drafting -> LaTeX or presentation production -> scientific visuals/tables -> academic voice edit -> re-render and inspect. Route only the needed stages; a citation-formatting request should not automatically trigger a full literature search, tool recommendation, or humanization pass. Recheck values, cite keys, frozen definitions and evidence scope after any prose/layout pass.

## Validation limits

This audit establishes local source coverage, hashes, text/manifest consistency, static implementation findings and dependency boundaries. It does not verify remote links or license claims against upstream, install host skills or dependencies, generate a research result, rehearse a talk, compile a manuscript, or certify rendered presentation/figure quality. The later active-only visual adapter and regression tests are a separate implementation step and must not change this provenance account.
