# Visualize and communicate

Inputs: actual data/evidence, audience, medium, final dimensions, time limit and requested source/export formats.

1. Read `visuals-scientific-visual-table-style` for scientific plots/tables. Freeze evidence and choose a form that answers the analytical question; preserve uncertainty, exact values and units. Select supplied references and templates as appropriate.
2. Generate with actual plotting tools or LaTeX specialists (`latex-pgfplots-charts`, `latex-tables`, `latex-tikz-diagrams`, `latex-figures-images`). Run appropriate source QA and inspect the final-size render. A helper PASS is not proof of complete visual or scientific QA.
3. For a talk read `academic-pptx`, `scholar-research-communication` and, for Beamer, `latex-beamer-slides`. Set audience take-home, evidence hierarchy, pacing and backup material. Use a real presentation backend to author PPTX; do not label a slide outline as a completed PPTX.
4. For a poster read `latex-academic-poster`, preserving legibility at final size. For lay communication use `evidence-plain-language-research` and `scholar-research-communication`; do not elevate association into causation.
5. Resolve contradictory source design examples through INTEGRATION.md. Inspect final exports and retain editable sources, speaker notes and source citations where requested.

Outputs: editable visual/deck/poster, requested exports, evidence/source references and render QA notes. Gate: final render inspected, numbers faithful, labels legible, citations present. A planned runtime is not a generated artifact.
