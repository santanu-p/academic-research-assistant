# Unified academic research plugin design

Authority: the complete goal-objective.md supplied on 2026-10-25. The user explicitly directs inspection, construction, integration, validation, and delivery. This document records implementation choices within that authorization.

The package will contain all 117 discovered skills as discoverable namespaced skills, their complete support trees, and a unified routing/onboarding skill. It will preserve all 174 input files and all 99 expanded archive files byte-for-byte under resources, including upstream metadata, install identity records, licenses, datasets, scripts, manuscripts, figures, and examples. Every original directory and archive member will have a destination and preservation hash where applicable.

Approaches considered: a remote service would require new hosting and would not execute local scripts; a skills-only collection would preserve instructions but provide weaker programmatic navigation; a local plugin with a small read-only MCP server supports the provided local assets and deterministic capability lookup. The third approach is selected as an implementation choice consistent with the supplied local collection. It does not invent external service connections.

Architecture: portable root plugin.json and mcp.json; synchronized Codex compatibility manifest; skills/<unique-name>/SKILL.md; resources/originals and resources/upstream; catalog/skills.json and routes.json; server/assistant_server.py; docs, workflows, reusable agent role instructions, audit reports, and executable tests. The server provides capability search, task routing, contained resource reads, dependency inspection, and provenance verification. It does not run research experiments, shell commands, or external requests on behalf of a tool call.

Active adapters add missing frontmatter, rewrite skill cross-references to unique names, fix relocatable paths, and scope broad studio activation to selected tasks. Academic content, original footer/disclosure obligations, examples, scripts, and license notices remain available. Conflict resolutions are documented and original instructions remain inspectable. User requests and evidence fidelity govern combined workflows. No synthetic research outcomes or connection claims are introduced.

External dependencies are explicit: host language model and filesystem tools; search/browser or scholarly connectors for live literature; TeX and converters for document builds; a presentation authoring backend for actual PPTX creation; scientific Python packages for plotting and ARMS calculations; Bash/WSL, Claude CLI, Codex CLI and TeX utilities for the optional adversarial loop. None are automatically installed or executed.

Verification includes official manifest schema checks, YAML/JSON and Python syntax, hash completeness, active local reference checks, namespace/routing fixtures, MCP subprocess lifecycle and tools, source QA scripts, representative small synthetic ARMS calculation, and visual inspection of a generated supplied-template figure. Expensive historical experiments and paid/authenticated workflows remain explicitly untested. Private Plugin Creator upload follows successful local package validation; its receipt and component diagnostics are inspected. Account saving does not prove desktop activation.

Distribution retains upstream attribution and terms. CC BY-NC components limit redistribution/use; packages without supplied license text are identified as rights unspecified. This is a private integration, with no assertion of public redistribution permission.
