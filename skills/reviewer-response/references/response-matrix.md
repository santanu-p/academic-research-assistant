# Response matrix and evidence record

Create one row per substantive comment component. Preserve the original reviewer's grouping and identifier so the final document can be read alongside the decision letter.

| Field | Purpose |
|---|---|
| comment_id | Editor or reviewer identifier plus component |
| original_comment | Original text or precise linked location |
| issue | Scientific or reporting question that must be answered |
| assessment | What the manuscript and evidence currently establish |
| action | Edit, analysis, clarification, justified disagreement, or open decision |
| evidence_required | Source, calculation, data, or author confirmation needed |
| affected_artifacts | Manuscript, supplement, code, figure, or reference files |
| execution_status | Proposed, underway, executed, checked, or unresolved |
| final_location | Current section, page/line, table, figure, or appendix |
| response_text | Direct answer consistent with verified work |

For added analyses, keep a short record of the question, reason for addition, data version, method, execution evidence, result, checks, and effect on the manuscript's conclusions. If a requested analysis was not performed, the response should say so and explain the scientific or practical reason. A future-work statement cannot be presented as a completed remedy.

For disagreement, use this logical structure: identify the specific request; state the relevant scientific reason; provide supporting evidence or argument; and explain any manuscript clarification that addresses the underlying concern. Avoid relying on authority, reviewer motives, or unsupported claims that the requested work is unnecessary.

Before closing a row, check the actual revised artifact and update its locator after the final build. Closure means the response accurately describes the current work, not necessarily that every request was accepted. Reconcile related comments so two responses do not make incompatible claims about the same method or result.
